Ember 的 11 項功能

Ember 自主開發了 11 種引擎。

Flow · Guard · Forge · Tone · Flare · Pulse · Boost · Kindle · Kiln · Spark · Lens。MetalFX、DXMT、D3DMetal 等第三方技術保留原名，只有 Ember 在其基礎上自主開發的功能才使用 Ember 名稱。

Windows 遊戲，在 Mac 上玩。

Ember 是在 Apple Silicon Mac 上執行 Windows 遊戲的啟動器。它為每款遊戲選擇合適的引擎與圖形轉換器，若啟動時當機，會換用其他轉譯器重試。同時提供自研的補幀、畫質提升與影格間隔調整功能。下方列出了各遊戲的測試範圍及 M4 Pro 實測效能。

如何閱讀影格率紀錄

請同時查看執行條件。

以下數值為本機（M4 Pro）實測，包含先前測量和截至10月23日的改動。結果隨場景和設定變化，不構成延遲保證。

遊戲 fps

遊戲實際繪製的影格數。同一款遊戲也會因地圖、解析度和設定而變化。

畫面輸出 fps

啟用影格生成時包含中間影格。Ember Flow 與遊戲內影格生成會分別標註。

測試範圍

選單、本機電腦對戰、試玩版和線上遊玩會分開標註。即使平均 fps 較高，若有卡頓或停滯也會註明。

10月18–20日測量

也關注反應與卡頓。

Ember Flow · 補幀

Rosetta · D3DMetal 流暢方式在《劍星》試玩版 FHD、MetalFX 關閉條件下，內部顯示延遲為 24.2 → 14.1 ms。

Ember Spark · 輸入延遲管理

DXMT 低延遲模式在遊戲能達到影格率上限時將顯示佇列自動設為 2 格，跟不上時設為 3 格。GPU 負載合成測試中，輸入→畫面延遲中位數為 49.7 → 37.8 ms，遊戲 fps +26%。Valheim 在 FEX、FHD、60 fps 上限、補幀關閉時，內部延遲為 10.2 → 5.6 ms。

失落的方舟 · 影格率改善

更早取得 GPU 結果後，擁擠場景的遊戲 fps 提升 +7%（50.2 → 53.7）。另一次重排比較中，每 1 秒最大影格時間的中位數從約 23–29 降至 17–20 ms。

本機（M4 Pro）實測。依據：10/18–19 smoothjob 顯示測量、10/19 spinless、10/20 fpslat·realign A/b16 比較。DXMT 內部延遲測量的是繪製佇列與顯示環節，不等同於輸入→畫面延遲。輸入→畫面以擷取合成路徑為基準，不包含顯示器自身延遲。未將不同測試的改善幅度相加。 查看測量條件

不止於在 Mac 上執行

遊戲啟動後，Ember 自研引擎便開始工作。Ember Flow · Forge · Tone · Flare · Pulse · Boost · Kindle · Kiln · Spark · Lens · Guard。點擊名稱旁的 i可查看原理及實測資料。

Ember Flow補幀

填補遊戲影格之間的空隙，同時管理延遲

Ember 自研補幀引擎在兩個遊戲影格之間繪製新影格。即使遊戲在 60~100fps 之間波動，也會在顯示器更新率（如 120、144Hz）範圍內均勻填補輸出。

  • 按需補格只補足缺少的影格，不拖慢遊戲本身。
  • 動態補償沿物體的移動軌跡產生中間畫面。
  • 文字保護Ember Guard 防止名稱標籤與 HUD 文字模糊拖影。
  • 延遲管理清空佇列並使用低延遲模式保持輸入反應。若補幀拖慢顯示，會暫停片刻以優先確保反應。《鬥陣特攻》（D3DMetal）開啟補幀後延遲為 44.5 → 25.2 ms。《致命公司》（Rosetta · DXMT，4K）的內部延遲為 51.5 → 43.0 ms。
  • 均勻輸出已修復延遲短暫超限就停止補幀的問題。《劍星》（D3DMetal，144Hz）先前各次測試畫面輸出在 72~117 fps 之間波動，平均值從 109.6 提升至 116.7 fps，延遲增加控制在 1 ms 以內。Rosetta D3DMetal 流暢方式改進顯示方法後，《劍星》FHD 延遲為 24.2 → 14.1 ms，輸出 116.6 → 119.2 fps(QHD 24.2 → 15.8 ms, 114.0 → 118.8 fps).
  • 減少長時間卡頓《七日世界》（Rosetta · D3DMetal · 4K）比較中，超過 50 ms 的卡頓從 6 次降至 0 次。這是單次工作階段結果，尚未確認整體輸出波動有所改善。
  • HDR 色彩保護D3DMetal 下的 HDR（PQ）遊戲會停止補幀、顯示原始影格，以保護色彩。已在《巫師 3》中確認無色彩或亮度異常。
  • 補幀 HUDEmber Lens 在畫面角落直接顯示 FG ON 和 LAT（延遲）。補幀暫停時也會顯示實際原因。
  • Flow 神經網路Ember 訓練的神經網路讀取動態資訊，產生中間畫面。自動模式預設使用此方式，4K 負荷約為原有方式的 60%。
  • 補幀引擎 1.6《失落的方舟》（FEX · DXMT）中，神經補幀略過次數從每 120 秒 76~133 次降至 0 次。
  • 水波與草叢即使場景中有細碎紋理，也能補幀，無需重複原始影格。
  • 先補幀，再放大與 MetalFX 配合時，以放大前的解析度進行補幀，降低 GPU 負擔。《失落的方舟》遊戲 fps 提升了 10%。
  • 輕量放大補幀影格不經過 MetalFX，而是使用輕量的單次處理放大。《失落的方舟》遊戲 49.7 → 51.6 fps，文字和 HUD 保持不變。
  • Ember Prism實驗功能，預設關閉。啟用後，Rosetta · D3DMetal 遊戲會使用 Apple 補幀引擎，優先確保畫質，延遲會略有增加。需在 macOS 26 或以上版本配合 Ember Flow 使用。

Ember Wayfinder
為無法啟動的遊戲依序尋找啟動組合，並可儲存。先嘗試已知啟動選項與推薦轉譯器，再檢查其他支援的轉譯器與引擎。Steam 遊戲在 Rosetta 下當機時，也會自動檢查共用同一安裝的 FEX 路徑。
尋找、儲存、還原

關閉附加功能，僅在已安裝的容器中嘗試。遊戲或 Wine 啟動器執行時不會開始，也不嘗試反作弊遊戲。每次嘗試後會關閉其開啟的遊戲與啟動器，並還原測試中修改的檔案。

已在 Valheim 和《巫師 3》中驗證啟動成功判定、設定儲存及還原。《巫師 3》的成功判定依據 D3DMetal 掛鉤、遊戲視窗和 CPU 活動等間接證據，不保證實際遊玩或長時間穩定性。

找到啟動組合後，必須點擊「儲存此設定」才會儲存。附加功能會保留，也可以開啟後重新驗證。已儲存的組態可透過「還原設定」復原。
